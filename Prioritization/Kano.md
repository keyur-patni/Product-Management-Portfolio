# Kano Model (Template + Examples)

The Kano Model helps product managers classify features based on how they impact customer satisfaction. It is especially useful early in discovery, during prioritization, and when evaluating which features create delight versus which are simply expected.

⭐ 1. Kano Categories

Each feature falls into one of five categories:

- Must‑Be — Basic expectations; without them, users are dissatisfied.

- Performance — The more you deliver, the happier users are.

- Delighters — Unexpected features that create excitement.

- Indifferent — Features that don’t impact satisfaction.

- Reverse — Features that some users love but others dislike.

⭐ 3. Kano Examples (Generic Portfolio Examples)

## A. Must‑Be Features (Basic Expectations)

These are essential. If missing → users are frustrated.
If present → users consider them “normal.”

### Examples:

- Login / authentication

- Password reset

- Basic navigation

- Error messages

- Data validation

### Clinic Example:

- “Check‑In button works reliably” → Must‑Be

- “Patient identity validation” → Must‑Be

## B. Performance Features (Linear Satisfaction)

The more you deliver, the happier users are.

### Examples:

- Faster load times

- More detailed analytics

- More customization options

### Clinic Example:

- “Real‑time status updates” → Performance

- “Wait time accuracy” → Performance

## C. Delighters (Exciters)

Unexpected features that create joy.

### Examples:

- Smart recommendations

- Auto‑scheduling

- Personalized insights

- Animated micro‑interactions

### Clinic Example:

- “Auto‑suggest best follow‑up time based on provider availability” → Delighter

- “Instant digital visit summary emailed to patient” → Delighter

## D. Indifferent Features

Users don’t care whether these exist.

Examples:

- Overly decorative UI elements

- Hidden advanced settings

- Rarely used filters

### Clinic Example:

- “Custom color themes for the dashboard” → Indifferent

## E. Reverse Features

Some users love them; others hate them.

### Examples:

- Auto‑play videos

- Forced animations

- Too much automation

### Clinic Example:

- “Auto‑advance through check‑in screens without user confirmation” → Reverse

⭐ 5. How PMs Use Kano in Real Work

Kano helps you:

- Identify which features must be built first

- Decide which features create competitive advantage

- Avoid wasting time on indifferent features

- Balance delighters with performance features

- Communicate prioritization decisions clearly to stakeholders

It’s especially useful during:

- Discovery

- Roadmapping

- Prioritization

- Sprint planning

- Stakeholder alignment

⭐ 6. Kano Best Practices

- Always validate Kano categories with user research

- Don’t over‑invest in delighters early

- Must‑Be features should be stable and reliable

- Performance features should be measurable

- Re‑evaluate Kano categories as user expectations evolve

⭐ 7. Kano Anti‑Patterns

Avoid these mistakes:

- Treating delighters as must‑be features

- Ignoring performance features that drive satisfaction

- Adding too many indifferent features

- Assuming user expectations without research

- Using Kano without linking to roadmap priorities
