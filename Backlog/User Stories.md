# User Stories (Template + Examples)

This file provides reusable user story formats that can be applied across any product or feature. It demonstrates clarity, structure, and alignment with the INVEST framework.

🧩 1. User Story Template (Standard Format)
Use this format for most features.

- As a \<type of user\>
- I want \<goal or action\>
- So that \<benefit or outcome\>

🧩 2. Examples of Well‑Written User Stories

## Patient Experience

- As a patient, I want to check in digitally so that I can avoid waiting at the front desk.

- As a patient, I want to see my current status so that I know where I am in the visit process.

- As a patient, I want to schedule a follow‑up appointment so that I can complete my care plan.

## Nurse / Triage

- As a triage nurse, I want to view patient priority levels so that I can triage patients efficiently.

- As a triage nurse, I want to update patient status so that the care team stays informed.

## Provider

- As a provider, I want to view lab results so that I can make informed decisions during the visit.

- As a provider, I want to see patient history so that I can provide accurate treatment.

## Admin / Operations

- As an admin, I want to track daily patient volume so that I can allocate staff appropriately.

- As an admin, I want to export visit data so that I can report on clinic performance.

🧩 3. User Story Template (Technical / Backend)
Use this when the story is more system‑driven.

- As a system, I need to validate user input so that incorrect data does not enter the workflow.
- As a system, I need to store visit timestamps so that wait times can be calculated accurately.

🧩 4. User Story Template (Error Handling)
Use this when the story involves validation or edge cases.

- As a user, I want to see clear error messages so that I can correct my input quickly.
- As a user, I want the system to prevent invalid submissions so that my data is accurate.

🧩 5. User Story Template (Admin / Reporting)
Use this for dashboards, analytics, or operational tools.

- As an admin, I want to filter reports by date so that I can analyze performance trends.
- As an admin, I want to download patient visit summaries so that I can share them with leadership.

🧩 6. INVEST Checklist (Quality Standard)
Every user story should follow INVEST:

- Independent — can be built separately

- Negotiable — not a contract

- Valuable — delivers user benefit

- Estimable — can be sized

- Small — fits within a sprint

- Testable — has clear acceptance criteria

🧩 7. Linking User Stories to Acceptance Criteria
Each user story should connect to acceptance criteria for clarity and testability.

🧩 8. Anti‑Patterns (What NOT to Do)
Avoid these common mistakes:

- Stories that describe implementation instead of user value

- Stories that are too large (should be broken down)

- Stories without acceptance criteria

- Stories that describe UI design instead of user intent

- Stories that include multiple goals in one sentence
